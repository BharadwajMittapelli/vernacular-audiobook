# Fix Book Deletion Failure and Synchronize Bookshelf/Recent Counts

## Diagnosis Summary

**Confirmed Root Cause:** CORS configuration blocks DELETE requests for `/api/studio/*` routes.

**Evidence:**
- Browser shows "Network Error" when clicking Delete — classic CORS preflight failure
- `server/src/index.js:40-45` CORS delegate allows `methods: ['GET', 'POST', 'OPTIONS']` — DELETE missing
- `/api/studio` route at line 101 goes through this CORS config (not the wildcard storefront path)
- `DELETE /api/studio/:bookId` endpoint exists and is correctly implemented in `studioRoutes.js:658-691`
- Frontend delete flow is correctly wired with confirmation dialog, loading state, error handling

## Verification Steps (Must Complete Before Implementation)

- Verify `req.path.startsWith('/api/storefront')` is false for `/api/studio/delete/book-id`

- Confirm `methods` array does NOT include `'DELETE'`

### No Backend Endpoint Changes
The existing `DELETE /api/studio/:bookId` endpoint already:
- Requires authentication (authMiddleware at line 101)
- Checks ownership (`.eq('user_id', req.user.id)`)
- Blocks deletion during processing (returns 409)
- Deletes from `books` table
- Response: `{ success: true, message: 'Book deleted successfully' }`

## Counts Synchronization (Already Correct)

Bookshelf and Recent counts are **derived** from the `books` state — not maintained independently:

```javascript
const sortedBooks = [...books].sort(...);
const bookshelfIds = new Set(sortedBooks.slice(0, 5).map(b => b.id));
const bookshelfBooks = sortedBooks.filter(b => bookshelfIds.has(b.id));
const recentBooksFull = sortedBooks.filter(b => !bookshelfIds.has(b.id));
// tabsWithCounts derives from these arrays
```

When `setBooks()` filters out the deleted book:
- All derived arrays recompute automatically
- Counts update without manual intervention
- No double-decrement risk
- Bookshelf may show same count if 6th book moves in
