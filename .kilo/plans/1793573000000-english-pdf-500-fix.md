# English PDF Upload 500 Debug & Fix Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Identify and fix the cause of HTTP 500 when uploading valid English PDFs (no `?language` param) to `/api/documents/upload`, where the error is caught by the route's outer try/catch (line 172-175).

**Architecture:** The upload route calls `pdfText()` which uses `pdf-parse` (v2.4.5) wrapping `pdfjs-dist`. The 500 occurs after successful text extraction, suggesting the error is in post-processing (`splitTextIntoChapters`), cleanup (`parser.destroy()`), or an unhandled async rejection from pdf.js worker threads.

**Tech Stack:** Node.js 22, Express, pdf-parse@2.4.5, pdfjs-dist@5.4.296, multer

**Spec:** This plan addresses the lingering 500 after previous fixes to Windows path resolution, error handling, and Multer error bubbling.

---

- Preserve existing API contract: 200 on success, 400/422 on client errors, 500 only on genuine server failures
- All errors must log full stack trace (`console.error(..., e.stack || e)`)
