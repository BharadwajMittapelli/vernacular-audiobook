# Phase 4 Sprint 4.2 (DEV B / Server): Asynchronous Job Queue

**Branch:** `dev-server` · **Scope:** `/server` only · **Role:** Dev B (Backend Lead)

## Goal
Add `POST /api/audio/synthesize-async` for multi-chapter bulk rendering. Jobs run asynchronously via BullMQ (Redis-backed) with an in-memory fallback when `REDIS_URL` is absent. When all chapters in a book complete, a notification stub fires. Existing sync endpoint is untouched.

---

## Decisions

### Decision 1 — Queue choice: BullMQ + in-memory fallback
- **Production path:** BullMQ (`bullmq` npm package) backed by Redis (configured via `REDIS_URL`).
- **Fallback path:** A lightweight in-memory Map-based queue when `REDIS_URL` is absent. Same interface, no durability across restarts.
- Conditional import: `bullmq` is a peer dependency loaded dynamically; if absent and `REDIS_URL` is set, log a clear error at startup instead of crashing.

### Decision 2 — Job model
Each job represents **one chapter**. A book is a logical grouping — a single API call enqueues N jobs and returns one `bookId`. Each chapter job:
- Already has its own `idempotency_key` in the request body (reuses existing constraint).
- Deducts credits only if it wins the placeholder INSERT race (same logic as sync, moved into the worker).
- Updates `audio_generations` when complete (same columns as sync).

### Decision 3 — Book-level tracking
Add `book_id` (UUID, nullable) to `audio_generations` rows created by the async path. All chapters in one book share the same `book_id`.
- A separate `books` table tracks aggregate status: `{ id, user_id, total_chapters, completed_chapters, webhook_url, status, created_at }`.
- When `completed_chapters === total_chapters`, fire `onJobComplete`.

### Decision 4 — Credit handling (MUST fix wallet drain)
**Upfront pre-check** (critical — prevents partial-book wallet drain): In the `POST /synthesize-async` handler, calculate `totalCost = sum(calculateCost(stripMarkdown(chapter.text)) for each chapter)`, query the user's current balance via a new RPC `get_user_balance(user_id)`, and if `balance < totalCost` return `402 { success: false, error: 'Insufficient credits. Required: N, Available: M }` **before inserting any placeholders or enqueuing jobs**. Actual per-chapter deduction stays inside the worker (atomic RPC, same rule as sync).

```sql
-- In migration 004 — atomic balance query for pre-flight check
create or replace function public.get_user_balance(p_user_id uuid) 
returns integer language plpgsql as $$
begin
  return (select credits from public.users where id = p_user_id);
end; $$;
```

If the user row doesn't exist, treat balance as 0 (return 402).

### Decision 5 — Atomic completion tracking (race guard)
**Fix read-modify-write race** when multiple workers complete simultaneously. Add `increment_book_completion` RPC to migration (see below). The worker calls this RPC instead of doing a Node-side SELECT → UPDATE → SELECT. The RPC does a single `UPDATE ... SET completed_chapters = completed_chapters + 1 WHERE id = p_book_id RETURNING completed_chapters, total_chapters` and returns the JSON. Worker compares returned `completed` vs `total` to decide whether to fire the webhook.

### Decision 5 — Notification: webhook stub
`onJobComplete(bookId)` makes a POST to `book.webhook_url` with `{ bookId, completedAt, chapters: [...] }`. If the POST fails or the URL is absent, log a warning — never block the book-complete event. This is a stub; DEV A wires up the real implementation.

### Decision 6 — Book failure handling
If a chapter job **fails** (TTS error, upload failure, refund succeeded), call `mark_book_failed(bookId)`: UPDATE `books.status = 'failed'`, set `completed_at = now()`. The webhook fires only on success. This prevents a book from hanging in `pending` forever when one chapter crashes.

### Decision 7 — Rate limiting
Skip the async endpoint from the global 5/min limiter; give it its own tighter limiter (max 2 books/min per IP) to prevent abuse of bulk operations.

### 1. MIGRATION: `server/migrations/004_async_queue_support.sql`
```sql
-- Phase 4.2: tables, columns, and RPCs for async bulk synthesis.
-- Safe to re-run (IF NOT EXISTS).

-- Track bulk book jobs.
create table if not exists public.books (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  total_chapters integer not null default 0,
  completed_chapters integer not null default 0,
  webhook_url text,
  status text not null default 'pending',
  created_at timestamptz not null default now()
);

-- Link async-generation rows to their parent book.
alter table public.audio_generations
  add column if not exists book_id uuid references public.books(id) on delete set null;

create index if not exists audio_generations_book_id_idx
  on public.audio_generations (book_id);

create index if not exists books_status_idx
  on public.books (status) where status != 'completed';

-- Atomic balance query for async pre-flight credit check.
create or replace function public.get_user_balance(p_user_id uuid)
returns integer language plpgsql as $$
declare v integer;
begin
  select credits into v from public.users where id = p_user_id;
  return coalesce(v, 0);
end; $$;

-- Atomic completion increment. Returns { completed, total }.
-- Handles concurrent completions safely; serializes via row lock.
create or replace function public.increment_book_completion(p_book_id uuid)
returns json language plpgsql as $$
declare
  v_completed integer;
  v_total     integer;
begin
  update public.books
     set completed_chapters = completed_chapters + 1
   where id = p_book_id
  returning completed_chapters, total_chapters
    into v_completed, v_total;

  if not found then
    raise exception 'BOOK_NOT_FOUND' using errcode = 'P0001';
  end if;

  return json_build_object('completed', v_completed, 'total', v_total);
end; $$;

-- Mark a book as failed (fires when any chapter job fails).
create or replace function public.mark_book_failed(p_book_id uuid)
returns void language plpgsql as $$
begin
  update public.books
     set status = 'failed'
   where id = p_book_id;
end; $$;
```

### 2. NEW `server/src/queues/synthesisQueue.js`
Exposes a single `synthesisQueue` object with:
- `isReady` — boolean (true when BullMQ connected, or in-memory mode active)
- `addJob(jobData)` — enqueue a chapter job
- `run(workerFn)` — start processing (no-op in in-memory fallback until called)
- `close()` — graceful shutdown hook

Conditional init pattern:
```javascript
let Queue = null;
try {
  const m = await import('bullmq');
  Queue = m.Queue;
} catch {
  // bullmq not installed; will use in-memory fallback
}

const redisUrl = process.env.REDIS_URL;
let queue;
if (Queue && redisUrl) {
  const { RedisConnection } = await import('bullmq');
  queue = new Queue('synthesis', { connection: { url: redisUrl } });
} else {
  queue = new InMemoryQueue(); // local minimal implementation
}
```

In-memory queue (local class, ~60 lines):
- `Map<string, Job>` storing pending jobs
- `addJob` pushes to map
- `run` polls every 500ms, calls worker on first-in-entry
- No persistence, no concurrency control (single-worker OK for MVP)

Job data shape:
```js
{
  generationId: string,   // pre-inserted placeholder row ID
  chapterId: string,
  text: string,
  language: string,
  voiceProfile: string,
  speed: number,
  userId: string,
  creditsUsed: number,
  bookId: string | null
}
```

Worker logic (mirror of sync route, refactored into a reusable function):
1. Select placeholder row (verify status='processing'). Skip if another worker already claimed it (idempotency check on row status — row must be 'processing', not 'completed' or 'failed').
2. Deduct credits (atomic RPC). If insufficient, mark row `failed` and return.
3. Call `synthesizeText(cleanText, language, voiceProfile, speed)`.
4. Call `uploadAudio(buffer, chapterId, format)` → get `{ audioPath, signedAudioUrl }`.
5. UPDATE `audio_generations` with all fields + `audio_path`, `audio_url = signedAudioUrl`, `status = 'completed'`.
6. Call `increment_book_completion(bookId)` RPC; if `result.completed === result.total`, fire `onJobComplete(bookId)`.
7. If failure: refund credits, UPDATE row `status = 'failed'`, call `mark_book_failed(bookId)` to mark the whole book failed.

Export `synthesizeChapterWorker(jobData)` for use by both the queue and a direct-test hook.

### 3. EDIT `server/src/routes/audioRoutes.js`
Add new route **after** the existing sync routes (preserves all existing behavior):

```javascript
// POST /api/audio/synthesize-async
router.post('/synthesize-async', async (req, res) => { ... });
```

Handler logic:
1. Validate payload: `{ chapters: [{ chapterId, text, language, voiceProfile, speed, idempotencyKey }], bookId?, webhookUrl? }`. Reject if `chapters` is empty or missing required fields.
2. Calculate `totalCost = sum(calculateCost(stripMarkdown(chapter.text)) for each chapter)`.
3. Upfront balance pre-check: `const balance = await get_user_balance(userId)`; if `balance < totalCost`, return `402 { success: false, error: 'Insufficient credits', required: totalCost, available: balance }` — **do not insert anything**.
4. Generate a new `bookId` (uuid) if not provided.
5. Insert `books` row: `{ id: bookId, user_id: userId, total_chapters: chapters.length, webhook_url: webhookUrl, status: 'pending' }`.
6. For each chapter, insert an `audio_generations` placeholder row with `book_id`, `status: 'processing'`, and `idempotency_key = bookId + '-' + chapter.idempotencyKey` (scoped to prevent cross-book collisions). If a placeholder already exists (unique constraint violation), reuse that existing `generationId` and skip re-enqueue.
7. For each chapter, call `synthesisQueue.addJob({ generationId, ... })`.
8. Return `202 { success: true, bookId, totalChapters: N, status: 'queued' }`.

## Risks / Known Gaps
- **In-memory queue is not durable** — restart loses all pending jobs. Acceptable for dev; documented upgrade path to Redis.
- **Single-worker in-memory fallback** — chapters process sequentially, not in parallel. Fine for MVP; parallel workers need Redis.
- **No retry logic in in-memory fallback** — failed jobs stay failed. BullMQ provides built-in retries.
- **Webhook stub** — `onJobComplete` is a logger; DEV A connects the real notification channel.
- **Async sync route not refactored** — the existing `POST /synthesize` keeps its current logic (not extracted into `synthesizeChapterWorker`) to avoid breaking changes. The worker export is separate and only used by the queue.
- **Existing sync polling logic (15 attempts × 500ms)** is still used by the sync endpoint and is unaffected.

---

## Out of Scope
- Real-time progress updates via WebSocket (client-side polling suffices for MVP).
- Per-job cancellation endpoint.
- Multi-worker horizontal scaling (requires Redis anyway).
- Email notifications (webhook is the extensibility point).
