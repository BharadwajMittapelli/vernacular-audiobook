# Audio Library: Album Artwork & Rename Features Plan

## Overview
This plan implements two features for the Audio Library:
1. **Custom Album Artwork Upload**: Allow users to upload `.jpg`/`.jpeg` artwork to replace placeholders.
2. **Rename Chapter Title**: Allow users to edit chapter titles inline, with auto-sync across All Audio and By Book sections.

## Current Codebase Understanding

### Database Schema
- `public.books` table has `title` and `cover_url` columns (migrations 006_add_book_metadata.sql)
- `public.chapters` table has `title` column linking to books via `book_id`
- Audio Library reads from `books` and `chapters` joined with `audio_generations` and `playback_history`

### Storage Infrastructure
- **Existing Bucket**: `audiobook` (private bucket)
- **Bucket Policies**:
  - "Authenticated users can read own files" (SELECT)
  - "Authenticated users can upload" (INSERT - no ownership validation)
  - "Service role full access storage" (ALL for service_role)
- **Books RLS**: "Users can update own books" - UPDATE with `(auth.uid() = user_id)`

### Key Components
| Component | File | Purpose |
|-----------|------|---------|
| Player Panel | `client/src/components/audioLibrary/PlayerPanel.jsx` | Displays chapter title, book cover |
| Audio List | `client/src/components/audioLibrary/AudioRow.jsx` | Shows chapter title in list |
| By Book View | `client/src/components/audioLibrary/ByBookView.jsx` | Shows chapter titles grouped by book |
| Storage Service | `server/src/services/storageService.js` | Supabase storage utilities |
| API Client | `client/src/services/api.js` | Frontend API functions |
| Library Routes | `server/src/routes/libraryRoutes.js` | Library API endpoints |

### Current Pattern for Private Storage
The application uses stable storage paths with on-demand signed URL generation:
- `storageService.js` has `getSignedAudioUrl(filePath, expiresInSeconds)` 
- `resolveAudioUrl(record)` generates fresh signed URLs for audio
- Libraries return signed URLs in API responses, not raw paths

**For artwork, we follow the same pattern:**
- Store stable path in `books.cover_url` (e.g., `artwork/<bookId>.jpg`)
- Generate fresh signed URL when returning to client
- Do NOT store expiring signed URLs permanently

## Feature 1: Album Artwork Upload

### Implementation Details

**1. UI Changes (PlayerPanel.jsx)**
- Make artwork container ALWAYS clickable (both empty and populated states)
- When no artwork: show placeholder initials + subtle "Add Image" icon overlay
- When artwork exists: show image + subtle Camera icon overlay (top-right of image, below favorite button)
- Add hidden `<input type="file" accept=".jpg,.jpeg">` triggered on click
- Preserve existing dimensions: `w-44 h-44 rounded-xl overflow-hidden bg-muted shadow-xl mb-4`
- Use `object-fit: cover` for uploaded artwork
- Do NOT interfere with favorite button (absolute positioned at top-right, icon positioned slightly offset)

**2. Storage Approach (Backend)**
- Reuse existing `audiobook` bucket
- Store artwork at stable path: `artwork/<bookId>.jpg`
- Upload using service role (bypasses bucket RLS upload policy limitations)
- Explicitly verify user owns the book before uploading
- Validate file: JPEG MIME type, .jpg/.jpeg extension, max 5MB
- Prevent cross-user artwork overwrites via ownership check

**3. Backend API (libraryRoutes.js)**
Add new endpoint:
```javascript
router.post('/artwork/:bookId', async (req, res) => {
  // 1. Verify user owns the book
  const { data: book, error } = await supabase
    .from('books')
    .select('id')
    .eq('id', req.params.bookId)
    .eq('user_id', req.user.id)
    .single();
  
  if (!book) return res.status(404).json({ success: false, error: 'Book not found' });
  
  // 2. Validate file (size, MIME, extension)
  // 3. Upload to storage with path: artwork/<bookId>.jpg
  // 4. Update books.cover_url with stable path only
  // 5. Return signed URL for immediate display
});
```

**4. Signed URL Generation**
Add helper to `storageService.js`:
```javascript
export async function getSignedImageUrl(filePath, expiresInSeconds = 3600) {
  const { data, error } = await supabase.storage
    .from(AUDIO_BUCKET)
    .createSignedUrl(filePath, expiresInSeconds);
  if (error) throw new Error(`Signed URL generation failed: ${error.message}`);
  return data.signedUrl;
}
```

Modify library routes to generate signed URLs for artwork:
```javascript
// In all-audio query and other book queries
const coverUrl = book.cover_url 
  ? await getSignedImageUrl(book.cover_url, 3600)
  : null;
```

**5. Frontend API (api.js)**
```javascript
export function uploadArtwork(bookId, file) {
  const form = new FormData();
  form.append('artwork', file);
  return api.post(`/api/library/artwork/${bookId}`, form, {
    headers: { 'Content-Type': 'multipart/form-data' }
  }).then((res) => res.data);
}
```

**6. Data Flow**
```
User clicks artwork (no artwork exists) → File picker opens → Select JPG/JPEG
→ API validates file → Upload to storage → Update books.cover_url with stable path
→ API returns fresh signed URL → PlayerPanel displays image
→ All views fetch book data → Generate signed URLs → Show artwork
```

### Security & Validation

**Client-side:**
- File input accepts only `.jpg`, `.jpeg`
- Show error before upload if file type invalid

**Server-side:**
- Verify JPEG MIME type: `image/jpeg`
- Verify extension: `.jpg` or `.jpeg`
- File size limit: 5MB (check `req.file.size`)
- Path sanitization: prevent directory traversal (`artwork/<bookId>.jpg` only)
- Ownership check: verify `books.user_id = req.user.id` before upload AND update

**Important:** The existing upload policy has no ownership validation. We MUST explicitly check book ownership in the route handler.

## Feature 2: Rename Chapter Title

### Confirmed Data Source
The rename feature targets **`chapters.title`** (not `books.title`).
- Displayed in PlayerPanel (main heading, line 72): `activeChapter.chapterTitle`
- Displayed in AudioRow (list item, line 40): `item.chapterTitle`
- Displayed in ByBookView chapter rows (line 158): `chapter.chapterTitle`

### Implementation Details

**1. UI Changes (AudioRow.jsx & ByBookView.jsx)**

Make chapter title editable:
```javascript
const [isEditing, setIsEditing] = useState(false);
const [editValue, setEditValue] = useState('');
const [error, setError] = useState('');
const [saving, setSaving] = useState(false);
const originalTitle = chapter.title;

// When clicking title
const handleClick = () => {
  if (!isEditing) {
    setEditValue(chapter.title);
    setIsEditing(true);
  }
};

// When saving
const handleSave = async () => {
  const trimmed = editValue.trim();
  if (!trimmed) {
    setError('Title cannot be empty');
    return;
  }
  if (trimmed === originalTitle) {
    setIsEditing(false);
    return;
  }
  
  setSaving(true);
  setError('');
  try {
    const result = await renameChapter(chapter.id, trimmed);
    // Update local state (props will propagate)
    onSuccess(result.title); // callback to parent
    setIsEditing(false);
  } catch (err) {
    setError(err.message || 'Failed to save');
    // Preserve original title on failure
  } finally {
    setSaving(false);
  }
};

// When cancelling
const handleCancel = () => {
  setIsEditing(false);
  setError('');
  setEditValue(originalTitle);
};
```

Render as either text or input:
```javascript
{isEditing ? (
  <input
    type="text"
    value={editValue}
    onChange={(e) => setEditValue(e.target.value)}
    onKeyDown={(e) => {
      if (e.key === 'Enter') handleSave();
      if (e.key === 'Escape') handleCancel();
    }}
    onBlur={() => !isEditing && handleCancel()}
    className="text-sm font-semibold text-foreground font-serif leading-tight border-b border-terracotta bg-transparent outline-none"
    autoFocus
    disabled={saving}
  />
) : (
  <p 
    onClick={handleClick}
    className="text-sm font-semibold text-foreground font-serif leading-tight cursor-text hover:bg-muted/50 rounded px-1 -mx-1 transition-colors"
  >
    {chapter.title}
  </p>
)}
{error && <span className="text-xs text-destructive">{error}</span>}
```

**2. Safe Editing Behavior**
- **Enter**: Save (trim whitespace, validate non-empty), prevent duplicate submissions during save
- **Escape**: Cancel, revert to original title immediately
- **Blur**: Cancel edit, revert to original title (do NOT auto-save on blur)
- **Empty title**: Show error, don't save, keep edit mode active
- **Whitespace-only**: Trim and reject as empty
- **Saving state**: Disable input, show loading indicator, prevent double-click
- **API failure**: Restore original title, show error message, keep edit mode active
- **Click outside**: Does NOT save (blur cancels instead)

**State Management Pattern:**
```javascript
const [isEditing, setIsEditing] = useState(false);
const [editValue, setEditValue] = useState('');
const [error, setError] = useState('');
const [saving, setSaving] = useState(false);
const originalTitleRef = useRef(chapter.title);

const handleSave = async () => {
  const trimmed = editValue.trim();
  if (!trimmed) { setError('Title cannot be empty'); return; }
  if (saving) return; // Prevent duplicate submissions
  
  setSaving(true);
  setError('');
  try {
    const updatedChapter = await renameChapter(chapter.id, trimmed);
    onSuccess(updatedChapter); // Pass full chapter object
    setIsEditing(false);
  } catch (err) {
    setError(err.message || 'Failed to save');
    setEditValue(originalTitleRef.current); // Restore original on failure
  } finally {
    setSaving(false);
  }
};

const handleCancel = () => {
  setIsEditing(false);
  setError('');
  setEditValue(originalTitleRef.current); // Always restore original
};

const handleBlur = () => {
  handleCancel(); // Blur cancels, doesn't save
};
```

**3. Backend API (libraryRoutes.js)**
Add new endpoint:
```javascript
router.put('/chapters/:chapterId/rename', async (req, res) => {
  const { chapterId } = req.params;
  const { title } = req.body;
  
  // Validate input
  if (!title || typeof title !== 'string' || !title.trim()) {
    return res.status(400).json({ success: false, error: 'Title is required' });
  }
  
  const trimmedTitle = title.trim();
  
  // Verify ownership: chapters has direct user_id column (confirmed from DB schema)
  const { data: chapter, error } = await supabase
    .from('chapters')
    .select('id, title, status, book_id')
    .eq('id', chapterId)
    .eq('user_id', req.user.id)
    .single();
  
  if (!chapter) {
    return res.status(404).json({ success: false, error: 'Chapter not found or access denied' });
  }
  
  // Update title, return full chapter object for frontend state sync
  const { data: updated, error: updateError } = await supabase
    .from('chapters')
    .update({ title: trimmedTitle })
    .eq('id', chapterId)
    .eq('user_id', req.user.id)
    .select('id, book_id, sequence_number, title, status')
    .single();
  
  if (updateError) throw updateError;
  
  res.json({ success: true, chapter: updated });
});
```

**4. Frontend API (api.js)**
```javascript
export function renameChapter(chapterId, newTitle) {
  return api.put(`/api/library/chapters/${chapterId}/rename`, { title: newTitle })
    .then((res) => res.data.chapter);
}
```

**5. Immediate Synchronization**
- After successful rename, parent component (AudioLibrary.jsx) updates local state
- Pass updated title through props to all child components
- Both All Audio and By Book views update instantly
- No page refresh needed

**6. What Does NOT Change**
- Chapter audio playback (`audio_generations`)
- Chapter sequence number
- Chapter text content
- Audio alignment data
- Book-level metadata
- Unrelated chapters

## Security Considerations

### Artwork Upload
- **File type**: Validate both extension (.jpg/.jpeg) AND MIME type (image/jpeg)
- **File size**: Reject files > 5MB
- **Ownership**: Explicitly check `books.user_id = req.user.id` before upload AND update
- **Path sanitization**: Use only `artwork/<bookId>.jpg` format, no user input in path
- **Service role**: Use service role key for upload to bypass restrictive bucket policies
- **Cross-user protection**: Cannot overwrite another user's artwork even with same bookId (different users have different bookIds)

### Chapter Rename
- **Ownership**: RLS policy ensures user can only update their own chapters
- **Input sanitization**: Trim whitespace, reject empty strings
- **Rate limiting**: Existing API limiter applies (60/min global)
- **Atomic update**: Single UPDATE query with WHERE clause for idempotency
