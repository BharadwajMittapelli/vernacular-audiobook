# Plan: DELETE /:bookId — Book Deletion Endpoint

**Scope:** `server/src/routes/studioRoutes.js` ONLY  
**Goal:** Allow users to delete a book; CASCADE constraints clean up chapters and audio_generations automatically.

---

## Context (verified)
- `books` table: FK `chapters.book_id → books.id ON DELETE CASCADE` (migration 005).
- `audio_generations.chapter_uuid → chapters.id ON DELETE CASCADE` (migration 005), so deleting a chapter cascades to audio_generations. Therefore deleting a book cascades: books → chapters → audio_generations.
- `POST /:bookId/synthesize-all` sets `books.status = 'processing'` during bulk synthesis. Delete must be blocked while processing (race condition guard).
- Route order: `GET /:bookId` ends at line 289. Insert `DELETE /:bookId` between line 289 and line 291 (`GET /chapters/:chapterId`).

---

## Implementation

### Insertion point
After the closing `});` of `GET /:bookId` (line 289), before the comment `// GET /chapters/:chapterId` (line 291).

### Endpoint body
```js
// DELETE /:bookId — permanently delete a book and cascade
router.delete('/:bookId', async (req, res) => {
  try {
    const { bookId } = req.params;

    const { data: book, error: bookError } = await supabase
      .from('books')
      .select('status')
      .eq('id', bookId)
      .eq('user_id', req.user.id)
      .single();

    if (bookError || !book) {
      return res.status(404).json({ success: false, error: 'Book not found' });
    }

    if (book.status === 'processing') {
      return res.status(409).json({ success: false, error: 'Cannot delete a book while it is being synthesized' });
    }

    const { error: deleteError } = await supabase
      .from('books')
      .delete()
      .eq('id', bookId)
      .eq('user_id', req.user.id);

    if (deleteError) throw deleteError;

    res.json({ success: true, message: 'Book deleted successfully' });
  } catch (error) {
    console.error('DELETE /studio/:bookId error:', error);
    res.status(500).json({ success: false, error: 'Internal server error' });
  }
});
```

---

## Design Decisions
- **CASCADE handling:** No explicit chapter/audio cleanup needed — DB FK constraints handle it automatically.
- **409 race guard:** Prevents deletion mid-synthesis (bulk or single-chapter). In-flight workers may still reference the book id briefly after this check but before their own update — acceptable given the detached worker model.
- **BOLA:** `.eq('user_id', req.user.id)` on both select and delete prevents horizontal privilege escalation.
- **No audit log:** Delete is permanent; if audit trail is needed later, add a soft-delete flag or archive table (YAGNI for now).
