# Plan: PUT /chapters/:chapterId — Chapter Text Editing

**Scope:** `server/src/routes/studioRoutes.js` ONLY  
**Goal:** Allow users to edit a chapter's title and raw text, recalculate `char_count`/`estimated_duration_seconds`, and reset status to `pending` so it becomes re-synthesizable.

---

## Context (verified)
- Route order: `GET /chapters/:chapterId` ends at line 334; `POST /chapters/:chapterId/synthesize` starts at line 336. New `PUT /chapters/:chapterId` goes between them.
- `stripMarkdown` already imported and used throughout.
- `estimated_duration_seconds` heuristic used in ingest endpoint (line 76): `Math.ceil(cleanText.length / 15)`. Use identical formula here for parity.
- `char_count` stores **stripped** length (not raw). Ingest pipeline strips before counting. Update must do the same to avoid drift.
- `chapters` table has `user_id` column (live schema confirmed). Existing `GET /chapters/:chapterId` fetches with `.eq('user_id', req.user.id)` — follow that pattern for BOLA on the single-chapter path (no `book_id` in the URL to scope transitively).
- No `audio_generations` deletion required by spec — orphaned audio rows are harmless; the next synthesis will produce a new row and `GET /chapters/:chapterId` already picks the latest completed generation by `created_at DESC`.

## Implementation

### Insertion point
After the closing `});` of `GET /chapters/:chapterId` (line 334), before the comment `// POST /chapters/:chapterId/synthesize` (line 336).

### Endpoint body
```js
// PUT /chapters/:chapterId — edit chapter title and text
router.put('/chapters/:chapterId', async (req, res) => {
  try {
    const { chapterId } = req.params;
    const { title, text_content } = req.body;

    // Validation: at least one of title or text_content must be provided
    if (title === undefined && text_content === undefined) {
      return res.status(400).json({ success: false, error: 'At least one of title or text_content must be provided' });
    }

    // BOLA & state guard
    const { data: chapter, error: chapterError } = await supabase
      .from('chapters')
      .select('id, status')
      .eq('id', chapterId)
      .eq('user_id', req.user.id)
      .single();

    if (chapterError || !chapter) {
      return res.status(404).json({ success: false, error: 'Chapter not found' });
    }

    if (chapter.status === 'processing') {
      return res.status(409).json({ success: false, error: 'Cannot edit chapter while synthesizing' });
    }

    // Data recalculation
    const updates = {};
    if (title !== undefined) {
      if (typeof title !== 'string' || !title.trim()) {
        return res.status(400).json({ success: false, error: 'title must be a non-empty string' });
      }
      updates.title = title.trim();
    }

    if (text_content !== undefined) {
      if (typeof text_content !== 'string' || !text_content.trim()) {
        return res.status(400).json({ success: false, error: 'text_content must be a non-empty string' });
      }
      const cleanText = stripMarkdown(text_content.trim());
      updates.text_content = cleanText;
      updates.char_count = cleanText.length;
      updates.estimated_duration_seconds = Math.ceil(cleanText.length / 15);
      updates.status = 'pending';
    }

    const { data: updated, error: updateError } = await supabase
      .from('chapters')
      .update(updates)
      .eq('id', chapterId)
      .eq('user_id', req.user.id)
      .select('id, sequence_number, title, char_count, estimated_duration_seconds, status')
      .single();

    if (updateError) throw updateError;

    res.json({ success: true, chapter: updated });
  } catch (error) {
    console.error('PUT /studio/chapters/:chapterId error:', error);
    res.status(500).json({ success: false, error: 'Internal server error' });
  }
});
```

---

## Design Decisions
- **At least one field required:** Returns 400 if neither `title` nor `text_content` is provided.
- **Optional fields:** Each field is independently optional. If omitted, existing value is preserved (supabase `.update()` only sets provided keys).
- **BOLA:** `.eq('user_id', req.user.id)` on both fetch and update — consistent with the existing `GET /chapters/:chapterId` pattern and required here because no `book_id` is in scope.
- **409 guard:** Prevents editing while synthesis is in progress (protects data integrity).
- **No audio cleanup:** leaving old `audio_generations` rows is acceptable (the GET endpoint picks the latest by `created_at DESC`); deleting them would add an extra query and risk race conditions with in-flight synthesis.
- **Status → `pending`:** Only set when `text_content` changes (since that's what affects synthesis eligibility). Title-only edits leave status untouched.
